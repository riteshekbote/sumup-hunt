## Lead 1: `auth.sam-app.ro` — Unauthenticated Dynamic Client Registration (RFC 7591)

| Gate | Answer |
|------|--------|
| Q1 Scope | **Yes** — sam-app.ro is SumUp-owned staging (CNAME confirms), program covers "all company-owned infrastructure" |
| Q2 Reachable | **Yes** — unauthenticated POST to `/oauth2/register` returns 201 with `client_id`+`client_secret`+`redirect_uri` |
| Q3 Impact | **High** — attacker can register arbitrary OAuth clients, mint `client_credentials` JWTs (confirmed), and choose arbitrary `aud` values; staging→prod key isolation confirmed but staging compromise still matters |
| Q4 Provable | **Yes** — `curl -X POST https://auth.sam-app.ro/oauth2/register -d '{"redirect_uris":["https://evil.com"],"client_name":"test"}'` → 201 (non-invasive) |
| Q5 Novel | **Yes** — staging with open registration absent from prod; no public report found |
| Q6 Not rejected | **Yes** — not on always-rejected list |
| Q7 Reasonable triager | **Yes** — open client registration on staging is a real auth/authz finding |

**Verdict: VALID**

| Field | Value |
|-------|-------|
| Proof steps | `curl -s -X POST https://auth.sam-app.ro/oauth2/register -H 'Content-Type: application/json' -d '{"redirect_uris":["https://example.com"],"client_name":"poc"}'` → 201 + `client_id`/`client_secret`. Then `curl -s -X POST https://auth.sam-app.ro/oauth2/token -d 'grant_type=client_credentials&client_id={id}&client_secret={secret}'` → 200 with JWT. |
| Impact | Attacker-controlled OAuth clients on staging; mintable JWTs (empty scope blocks resources but token is valid at gateway). Staging environments often lack prod hardening. |
| CVSS 3.1 | **7.5** (AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N) |
| Channel | bugs.olivermaicher.eu |

## Lead 2: `api.sumup.com/authorize` — Client-ID Oracle + Wildcard CORS

| Gate | Answer |
|------|--------|

| Q3 Impact | **Medium** — client-ID enumeration reveals which OAuth apps are registered; wildcard CORS (`Access-Control-Allow-Origin: *`) on an auth endpoint could enable cross-origin token theft in browser flows |
| Q4 Provable | **Yes** — `curl -I 'https://api.sumup.com/authorize?client_id=dashboard&redirect_uri=https://evil.com'` shows error differentiation + CORS header |

| Q6 Not rejected | **Yes** — not CSRF-on-logout or clickjacking |
| Q7 Reasonable triager | **Yes** — oracle + misconfigured CORS on auth endpoint is accepted |

| Field | Value |

Repeat with `client_id=dashboard` → contains `invalid_request`. `curl -sI 'https://api.sumup.com/authorize?client_id=dashboard'` → `access-control-allow-origin: *`. |
| Impact | Oracle leaks registered client IDs; wildcard CORS on auth endpoint enables cross-origin read of auth responses in browser context. |
| CVSS 3.1 | **5.3** (AV:N/AC:L/PR:N/UI:N/S:U/C:L/I:L/A:N) |
